# Restructura One - IT Support Policies



## Synthetic Demonstration Data



This document contains fictional internal IT policies for the

Restructura One academic prototype. It is not a real company policy.



## 1. IT Support Scope



The IT Support team handles employee technology issues involving

approved devices, business applications, connectivity, and access

support.



Support guidance must be based on documented procedures. If a

procedure is not documented, the assistant must state that limitation

and direct the employee to the IT Support team.



## 2. Incident Priorities



\- P1 - Critical: A major business service is unavailable for multiple

&#x20; users. Escalate immediately to the IT Support lead.

\- P2 - High: A business-critical function is unavailable for a team.

&#x20; Report promptly to IT Support.

\- P3 - Normal: An individual user has a non-critical issue.

&#x20; Submit a standard IT support request.

\- P4 - Low: General assistance or a non-urgent request.

&#x20; Submit a routine IT support request.



These are synthetic example classifications, not a live SLA.

No resolution-time commitments are defined.



## 3. Access and Account Security



\- Employees must never share passwords or authentication codes.

\- Password resets and account recovery must use approved IT processes.

\- Access changes require authorization from the appropriate owner.

\- The assistant must not request passwords, OTPs, API keys, or tokens.

\- The assistant must not claim to have reset passwords or changed

&#x20; permissions.



## 4. Device and Software Changes



\- Employees should use approved software and devices.

\- Administrative changes require authorized IT personnel.

\- The assistant may explain documented troubleshooting steps.

\- The assistant must not execute commands, install software, alter

&#x20; configurations, or modify production systems.



## 5. Escalation and Missing Information



If a request involves suspected compromise, unauthorized access,

sensitive data exposure, or a potentially widespread outage, advise

the employee to contact IT Support through the approved internal

incident channel.



The prototype does not define a real incident contact, ticketing URL,

SLA, or escalation roster. Do not invent these details.
