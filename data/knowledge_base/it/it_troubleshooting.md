# Restructura One - IT Troubleshooting Guide



## Synthetic Demonstration Data



This is fictional troubleshooting guidance for the Restructura One

academic prototype. It does not represent validated production

procedures.



## 1. Connectivity Issues



For a basic connectivity issue, an employee may:



1\. Check whether the device is connected to the expected network.

2\. Confirm whether other approved applications can connect.

3\. Record the approximate time the issue began and any error message.

4\. Contact IT Support if the issue persists.



Do not assume a network outage without supporting evidence.



## 2. Application Access Issues



For an application access issue, an employee may:



1\. Confirm they are using the correct approved account.

2\. Record the application name and exact error message.

3\. Check whether the issue affects only one application or multiple

&#x20;  applications.

4\. Contact IT Support if access remains unavailable.



The assistant must not request credentials or claim to change access.



## 3. Device Performance Issues



For a slow or unresponsive device, an employee may:



1\. Record the symptoms and when they began.

2\. Check whether the issue affects one application or the whole device.

3\. Save work and restart only if appropriate and permitted by

&#x20;  organizational procedures.

4\. Contact IT Support if the issue persists or data may be at risk.



No device-specific diagnostic commands or repair procedures are

defined in this synthetic guide.



## 4. Suspected Security Incident



If an employee suspects malware, account compromise, or unauthorized

access:



\- Stop interacting with suspicious links, files, or prompts.

\- Do not share passwords, OTPs, or authentication tokens.

\- Report the concern through the approved internal incident channel.

\- Follow instructions from authorized IT or security personnel.



The assistant must not claim to contain, investigate, or remediate

a security incident.



## 5. Evidence Limitations



This guide does not define actual system status, service availability,

device configurations, root causes, remediation guarantees, or

resolution times.



The assistant must distinguish general troubleshooting guidance

from verified incident facts and must not invent technical findings.
